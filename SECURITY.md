# Проверка безопасности

Область проверки: публичный интерфейс, серверные маршруты SmartNation и администратора, сервис ДЗ и Worker настроек. Реальные оценки, токены, ИИН и пароли не должны попадать в issue, screenshot, HAR или отчёт.

## Права и хранение

- Публичный читатель видит расписание, календарь, книги и одобренные задания.
- Автор предложения ДЗ определяется случайным cookie устройства, а не введённым именем. Очистка cookie теряет привязку. Отдельной проверки личности автора ДЗ нет.
- Староста получает доступ к одной группе по случайному коду. Сервер хранит хеш кода и проверяет его версию; ротация отзывает старые сессии.
- Администратор использует отдельный случайный токен; на сервере задан его SHA-256. Восьмичасовая сессия администратора зашифрована и привязана к актуальному хешу.
- SmartNation подключается только к фиксированному HTTPS-домену. Пароль нужен для одного входа. Обновление использует зашифрованную общую сессию и блокировку на аккаунт.
- Worker принимает операции хранилища подключений только с серверным bearer-секретом. Ключ шифрования находится отдельно, в окружении приложения Vercel.

## Дополнительные ручные сценарии

Используйте отдельные локальные/тестовые окружения, фиктивные аккаунты и файлы.

| Проверка | Ожидаемый результат |
| --- | --- |
| PATCH `/api/smartnation` с чужим Origin | 403 без обращения к SmartNation |
| GET `/api/admin` без авторизации | 401 |
| POST входа администратора с фиктивным неверным токеном | Отказ, сессия администратора не выдаётся |
| Изменение одного байта зашифрованного cookie | Отказ в чтении сессии |
| Повторное использование одноразового кода устройства | Отказ; код уже использован |
| Истёкший код устройства | Отказ без расширения срока доступа |
| Работа двух разных аккаунтов | Подключение и оценки одного не доступны другому |
| ДЗ другой группы или чужое неподтверждённое вложение | Отказ либо отсутствие записи в выдаче |
| HTML/SVG/исполняемый файл под видом вложения | Отказ по типу/сигнатуре; HTML не исполняется inline |
| Вложение больше 4 МБ или более 5 вложений | Отказ |
| Текст `<script>alert(1)</script>` в задании | Обычный текст, без выполнения скрипта |
| SQL-подобный текст в задании | Сохраняется как строковое значение; структура запроса не меняется |

Пример безопасной проверки Origin для локального приложения:

```sh
curl -i -X PATCH http://localhost:3000/api/smartnation \
  -H 'Origin: https://example.invalid' \
  -H 'Content-Type: application/json' -d '{}'
```

Не добавляйте реальные cookie к этому примеру. Более подробная инструкция запуска тестов находится в корневом README.

## Границы гарантий

1. AES-GCM скрывает представление кеша на диске, но не защищает от уже исполняющегося скрипта того же origin или человека с доступом к разблокированному браузеру. Ключ IndexedDB используется этим браузером для расшифровки.
2. TLS и флаги cookie зависят от production-хостинга. Локальная HTTP-среда имеет другие условия.
3. Ограничители входа на Vercel работают в памяти отдельного прогретого процесса. Это не глобальная распределённая защита от перебора. Для более строгого ограничения нужен отдельный общий лимитер/WAF.
4. Проверка сигнатур файлов не является антивирусом. Документы и архивы могут содержать вредоносное содержимое; не открывайте недоверенные файлы с разрешёнными макросами.
5. Срок доступа проверяется сервером, но истёкшие зашифрованные объекты могут оставаться в R2 до очистки. Пароли и снимки оценок в эти объекты не записываются.
6. Безопасность внешних сервисов, изменение SmartNation API и права на подключённые материалы не определяются этим репозиторием.
7. Тесты с фикстурами не заменяют реальный аудит сервера, политик облачного аккаунта, зависимостей и конфигурации. Пустой отчёт `npm audit` не гарантирует отсутствия неизвестных уязвимостей.

## Сообщение об уязвимости

Сообщите владельцу репозитория по закрытому каналу. Если на GitHub доступна кнопка **Security → Report a vulnerability**, используйте её. Не публикуйте рабочие токены или данные студентов в обычном issue. Укажите commit SHA, компонент, минимальный пример на синтетических данных и наблюдаемый результат.
