# Сервис домашних заданий

Cloudflare Worker с D1 (`DB`) и R2 (`BUCKET`). `app/api` содержит маршруты ДЗ, вложений, старост, календаря и Web Push. `lib` содержит проверки прав, ограничения загрузок и очередь уведомлений. Схема и миграции находятся в `db` и `drizzle`. Интерфейс этого каталога сохранён для сервиса; основной сайт находится в соседнем `campus-vercel`.

## Сборка и локальная среда

Нужен Node.js 22. Сначала `npm ci`, затем `npm run build`. Для запуска сервиса используйте `npm run dev`. Файл `.env.example` содержит пустые поля для локального заполнения; рабочий `.dev.vars` не включён. Адаптер хостинга, его конфигурация `.openai/hosting.json` и обязательные лицензии сохранены. Развёртывание на новом аккаунте требует своих привязок базы, бакета и переменных среды; идентификатор существующего проекта не даёт доступа к его данным.

Для новой локальной базы выполните все три SQL-миграции из `drizzle/` по порядку с помощью `wrangler d1 execute DB --local --file ...` и конфигурации локального Worker. Не выполняйте миграции с `--remote` на рабочей базе во время проверки.

## Права

Предложение ДЗ и его файлы приватны для автора и старосты выбранной группы до одобрения. Автор определяется случайным cookie устройства; введённое имя не подтверждает личность. Староста ограничен своей группой. Одобрение, отклонение и закрытие записываются в журнал. Привязка вложений к новому заданию выполняется в одной транзакции.

Коды старост задаются в `MODERATOR_CODES_JSON` в виде хешей. `BACKEND_PROXY_SECRET` должен совпадать с серверным значением приложения. Для Web Push используются `PUSH_PUBLIC_KEY`, `PUSH_PRIVATE_JWK` и `PUSH_CONTACT`. Не помещайте реальные значения в репозиторий.

Проверка безопасности и известные ограничения: [корневой README](../README.md), [SECURITY.md](../SECURITY.md). Удалены неиспользуемые компоненты стартового UI и локальные кеши; рабочие API и обязательные адаптеры сохранены.
