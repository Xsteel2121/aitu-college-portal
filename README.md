# AITU College

Студенческий портал: расписание 30 групп, домашние задания с модерацией и вложениями, учебный календарь, библиотека, карта колледжа и личная успеваемость.

**Сайт:** https://aitu-college.vercel.app/

**Состояние проверки на 20 октября 2026:** основное приложение проходит тесты и сборку; npm-аудит его зависимостей не нашёл известных уязвимостей. В зависимостях вспомогательного сервиса ДЗ обнаружено 30 предупреждений, в том числе 21 высокого и 1 критического уровня. Это требует отдельного устранения и повторной проверки. См. [отчёт](docs/security-verification-2026-10-20.md). Репозиторий не является свидетельством полной безопасности рабочего сайта.

Расписание и подтверждённые задания открыты всем. Для оценок можно подключить личный кабинет College SmartNation, импортировать свою выгрузку или открыть демо. Симулятор изменяет только локальные расчёты.

## Структура

| Каталог | Назначение |
| --- | --- |
| `campus-vercel/` | Основное приложение: Next.js 16, React 19, TypeScript, серверный коннектор SmartNation |
| `campus-web/` | Сервис ДЗ, модерации, вложений и Web Push; Cloudflare D1 и R2, адаптер хостинга |
| `portal-control/` | Worker с настройками портала, обезличенными счётчиками и зашифрованным хранилищем подключений |
| `scripts/check-source.py` | Проверка состава публикации и распространённых форматов секретов |
| `SECURITY.md` | Модель доступа, ограничения и сценарии ручной проверки |

`campus-web` содержит также прежний интерфейс сервиса; текущий публичный интерфейс находится в `campus-vercel`. Конфигурация адаптера хостинга и лицензии включены там, где необходимы для сборки. В репозитории нет базы пользователей, реальных оценок, паролей, токенов доступа и выгрузки рабочего хранилища.

## Запуск

Нужны Node.js 22 и npm, для проверки публикации — Python 3. Команды выполняются из корня репозитория:

```sh
npm --prefix campus-vercel ci
cp campus-vercel/.env.example campus-vercel/.env.local
npm --prefix campus-vercel run dev
```

Откройте http://localhost:3000. Демо, локальный импорт оценок, расписание, книги и симулятор доступны без учётных данных SmartNation. Общие ДЗ и полноценное подключение требуют настроенных серверных сервисов. Не используйте чужое рабочее хранилище при проверке записи.

Для Vercel укажите **Root Directory: `campus-vercel`**, preset **Next.js**, Node.js **22.x**. Секреты задаются в переменных окружения хостинга; `.env.local` нельзя коммитить.

| Переменная | Назначение |
| --- | --- |
| `SMARTNATION_SESSION_SECRET` | Случайный серверный ключ не короче 32 символов; шифрование сессий и подключений |
| `CAMPUS_API_URL` | HTTPS-адрес своего сервиса ДЗ |
| `BACKEND_PROXY_SECRET` | Общий секрет прокси и сервиса ДЗ |
| `PORTAL_CONTROL_URL` | HTTPS-адрес своего Worker настроек и подключений |
| `PORTAL_SERVICE_SECRET` | Секрет серверного доступа к этому Worker |
| `PORTAL_ADMIN_TOKEN_HASH` | SHA-256 отдельного случайного токена администратора |

Ни одна из этих переменных не должна иметь префикс `NEXT_PUBLIC_`. Ключи Web Push, коды старост и привязки D1/R2 настраиваются отдельно в сервисах. Файл `docs/reminders-workflow.example.yml` — пример расписания уведомлений, он не запускает рассылку в этом репозитории автоматически.

## Как проверить безопасность

Проверка должна опираться на исходный код и повторяемые результаты. Наличие HTTPS, открытого репозитория или шифрования само по себе не доказывает безопасность всего приложения.

### 1. Повторить автоматические проверки

После клонирования выполните:

```sh
python3 scripts/check-source.py
npm --prefix campus-vercel ci
npm --prefix campus-vercel test
cd campus-vercel
npx tsc --noEmit
npm run build
npm audit --audit-level=high
cd ../campus-web
npm audit --package-lock-only --audit-level=high
```

Соседний каталог `portal-control` нужен для полного набора интеграционных тестов. Workflow **Security and build checks** повторяет эти команды на GitHub без доступа к секретам production. Проверяйте результат для конкретного commit SHA во вкладке **Actions**, а не только значок в README.

Тесты используют вымышленные данные и HTTP-фикстуры. Они проверяют:

- парсеры и расчёты оценок, отказ от чужих/неоднозначных журналов;
- шифрование сессии и браузерного кеша, отказ при подмене шифротекста, удаление кеша и ключа при выходе;
- проверку Origin, сессию администратора и сохранение настроек;
- разделение аккаунтов, обновление общих токенов, блокировку параллельного обновления;
- одноразовость и срок действия кода второго устройства, повторное подключение после отзыва сессии SmartNation.

`check-source.py` обнаруживает запрещённые локальные файлы и некоторые распространённые токены. Это базовый контроль состава публикации, он не заменяет полноценный сканер секретов, проверку истории Git и ручной аудит. `npm audit` проверяет только известные npm уязвимости на момент запуска.

### 2. Проверить границы доступа по коду

| Что проверять | Файлы |
| --- | --- |
| Пароль не сохраняется, запросы ограничены доменом SmartNation | `campus-vercel/lib/smartnation.server.ts` |
| Cookie зашифрован, HttpOnly, Secure в production; обработка Origin | `campus-vercel/app/api/smartnation/route.ts` |
| Хранилище подключений содержит шифротекст; доступ к аккаунтам разделён | `campus-vercel/lib/smartnation-broker.server.ts`, `portal-control/worker/index.js` |
| Кеш оценок зашифрован; ключ хранится отдельно в IndexedDB | `campus-vercel/lib/grade-cache.ts` |
| Администратор проверяется на сервере | `campus-vercel/lib/portal.server.ts`, `campus-vercel/app/api/admin/route.ts` |
| Прокси не принимает произвольный адрес назначения | `campus-vercel/app/api/[...path]/route.ts` |
| Староста ограничен своей группой; SQL использует привязанные параметры | `campus-web/lib/moderator.ts`, `campus-web/app/api/homework/` |
| Вложения проверяются и выдаются с учётом прав | `campus-web/lib/attachments.ts`, `campus-web/app/api/attachments/` |

### 3. Проверить браузером на тестовых данных

1. Откройте «Оценки» → демо. Добавьте виртуальную оценку: меняется только локальный расчёт, запросов записи в SmartNation нет.
2. Импортируйте свою тестовую CSV/JSON/XLSX выгрузку. В Network не должно быть запроса отправки содержимого этого файла на сервер.
3. При обычном входе пароль передаётся по HTTPS серверу портала, затем SmartNation. В коде нет сохранения пароля; сервер всё же получает его во время обработки запроса. Проверяющий должен отдельно доверять развёрнутому серверу.
4. В DevTools → Application посмотрите localStorage/sessionStorage: кеш оценок представлен зашифрованным конвертом, а cookie сессии недоступен через JavaScript. Проверьте флаги HttpOnly, Secure и SameSite в production. Не публикуйте значения cookie.
5. Нажмите «Выйти»: кеш и ключ в IndexedDB должны удалиться, cookie сессии — истечь. Кнопка выхода не завершает сессии на других устройствах.
6. В отдельном **тестовом** развёртывании предложите ДЗ и файл. До одобрения другой студент их не видит. Староста группы A не должен одобрять или удалять записи группы B. Подтверждённое ДЗ студент изменять не может.

Дополнительные случаи и известные ограничения перечислены в [SECURITY.md](SECURITY.md). Не запускайте нагрузочные проверки и подбор паролей на SmartNation или рабочем сайте.

## Данные и ограничения

- Пароли SmartNation не записываются в БД, кеш или хранилище подключений. ИИН и логин не добавляются в локальный снимок оценок. Cookie/токены SmartNation хранятся на серверной стороне только в зашифрованном виде.
- «Запомнить меня» ограничивает сессию семью днями; без него срок — восемь часов. Код другого устройства действует до десяти минут, используется один раз и не продлевает доступ сверх срока выдавшего устройства.
- SmartNation может отозвать свою сессию. Портал сохраняет кеш и предлагает переподключение; он не может отменить решение внешнего сервиса.
- Средние и стипендия — расчёт по текущим оценкам, без официальных кредитных весов и решения колледжа. Пороги по умолчанию: 70 и 90, их меняет администратор.
- Книги загружаются с публичных адресов источника; копии учебников в репозитории не распространяются. Карта колледжа — внешний встроенный сайт. Права на учебники и материалы сохраняются у правообладателей.
- Исходники доступны для проверки. Отдельная лицензия на весь проект не предоставляется; лицензии включённых сторонних компонентов сохраняются.

Этот репозиторий позволяет проверить опубликованный код. Сам по себе он не подтверждает, что production запущен именно из данного commit: для этого владелец должен сопоставить commit, конфигурацию и артефакт деплоя. Успешные тесты не являются независимым заключением о полной защищённости.
